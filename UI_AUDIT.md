## 0. Важное уточнение по формату проекта

Это **не** C-проект на ESP-IDF/LVGL. Это **ESPHome-конфигурация** (~3 700 строк YAML),
из которой ESPHome генерирует `main.cpp` (2.9 МБ) и собирает через ESP-IDF.

Практические следствия для ТЗ:

| Пункт исходного ТЗ | Как он ложится на ESPHome |
|---|---|
| `ui/ui_theme.h` / `ui_theme.c` | Нет C-файлов. Эквивалент — YAML-пакет токенов + `lvgl.theme` + `!include` с `vars` |
| Переиспользуемые `lv_style_t` | ESPHome LVGL **не отдаёт** `lv_style_t` наружу. Переиспользование делается через `theme:` и параметризованные `!include`-шаблоны |
| `screen_x_create()` / `_destroy()` | Страницы LVGL в ESPHome создаются **один раз статически** и живут вечно. **Утечек объектов нет и быть не может** — этот пункт снимается |
| Мьютексы / `lv_async_call` | Всё выполняется в единственном `loop()` ESPHome, который же крутит LVGL. **Гонок нет** — этот пункт тоже снимается |
| `ui_strings.h` | Эквивалент — один YAML-файл `substitutions` со строками |

То есть два самых страшных класса проблем из ТЗ (утечки экранов и thread-safety) здесь
**отсутствуют по конструкции**. Зато остальные — дизайн-система, вёрстка, состояния,
дубли — присутствуют в полном объёме.

## 1. Факты разведки

### 1.1 Версия LVGL
- **LVGL 9.5.0** — жёстко закреплена ESPHome 2026.8.2
  (`esphome/components/lvgl/__init__.py:161` → `LVGL_VERSION = "9.5.0"`),
  подтверждено физически: `.esphome/build/.../managed_components/lvgl__lvgl/lv_version.h`.
- Сырые лямбды в проекте используют `lv_label_set_text`, `lv_obj_set_style_bg_color`,
  `lv_obj_set_style_text_color`, `lv_arc_set_value`, `lv_slider_set_value`,
  `lv_obj_set_width/height`, `lv_obj_get_width/height`, `lv_color_hex`, `LV_PART_MAIN`,
  `LV_ANIM_ON` — **всё это валидный API LVGL 9.x**. Несовместимостей 8↔9 не обнаружено.

### 1.2 Железо и дисплей
| Параметр | Значение | Где |
|---|---|---|
| MCU | ESP32-S3 (`esp32-s3-devkitc-1`), 240 МГц, flash 16 МБ | `device.yaml:8-14` |
| PSRAM | есть, **octal @ 80 МГц** | `device.yaml:20-22` |
| Дисплей | `qspi_dbi`, модель `JC4832W535` | `device.yaml:45-58` |
| Разрешение | **320 × 480** (портрет), ротация не задана | `device.yaml:48-50` |
| Глубина цвета | 16 бит (RGB565) — дефолт ESPHome LVGL | `lvgl/__init__.py:590` |
| Буфер кадра | `buffer_size` **не задан** → дефолт `0` → **полный кадр 320×480×2 = 300 КБ**, **один** буфер, размещается **в PSRAM** | `lvgl/__init__.py:596`, `lvgl_esphome.cpp:755-786` |
| `full_refresh` | `false` (дефолт) | — |
| `draw_rounding` | 2 (дефолт) | — |
| Обновление дисплея | `update_interval: never` — кадры гонит LVGL | `device.yaml:57` |
| Тач | `axs15231` по I²C 0x3B, опрос 50 мс | `device.yaml:60-65` |

### 1.3 Способ ввода
**Только тач.** Ни `encoders:`, ни `keypads:` в конфиге нет.
Соответственно `lv_group` / фокус / видимый индикатор фокуса **не нужны** —
модель навигации прямая, по нажатиям. Пункт ТЗ про энкодер снимается.

### 1.4 Карта экранов

```
lvgl.pages  (создаются один раз, статически, не удаляются)
├── splash        skip:true  → on_load: script go_home
├── bedroom       (домашняя, ${home_page})
├── living_room
├── bathroom
├── corridor
├── outdoor
├── energy
├── climate
└── air_alerts

lvgl.top_layer  (поверх всех страниц И поверх header/footer)
├── titlebar          (header,  50 px, TOP_MID)
├── navbar            (footer,  50 px, BOTTOM_MID)
├── boot_screen       (100%, скрывается по on_client_connected / on_press)
├── settings_panel    (100%, hidden, показ по long-press на titlebar или клику по chevron)
├── light_control_panel  (100%, hidden, показ по long-press на RGB-кнопке)
└── climate_control_panel(100%, hidden, показ по клику на карточку климата)
```

- Переключение: `lvgl.page.next` / `previous` (кнопки footer), `page_wrap: true` (дефолт) → карусель.
- **Стека «назад» нет.** Панели — модальные оверлеи, закрываются только крестиком.
  Для карусели из 8 равноправных страниц это адекватная модель; отдельный back-stack не нужен,
  но **предсказуемое место закрытия оверлея** должно быть одинаковым (сейчас крестик
  в трёх панелях имеет три разных размера: 50, 45, 42 px).
- **Утечек нет** (статическое создание).

### 1.5 Как построена вёрстка сейчас

| Механизм | Где применяется | Доля |
|---|---|---|
| `layout: FLEX` | корневой контейнер каждой страницы (ROW_WRAP), footer (ROW), три панели (COLUMN), ряды кнопок в панелях | внешний каркас — **хорошо** |
| Абсолютные `x`/`y` + `align` | **всё содержимое карточек**: иконка `x:-10`, подпись `x:30,y:-18`, значение `x:30,y:14`, текст кнопки `x:62`, температуры `x:-60/-12`, заголовки `x:72,y:16/40` | внутренности — **плохо** |
| `lv_obj_align_to` | не используется нигде | 0 |
| `LV_GRID` | не используется нигде | 0 |

Каркас на flex — правильный. Но **каждая карточка внутри свёрстана пиксельными смещениями**,
причём один и тот же паттерн «иконка + подпись + значение» скопирован **18 раз** в 7 файлах
страниц (`grep "y: -18" layouts/pages/` → 18 совпадений).

### 1.6 Стили

- Тема есть: `layouts/themes/main.yaml` — 18 строк, покрывает `obj`, `button`, `bar`, `dropdown`.
  Это единственный островок дизайн-системы.
- **249 хардкод-цветов** в YAML, **39 уникальных значений**
  (`0x888888` — 46 раз, `0x555555` — 21, `0x42495A` — 21).
- Семантических токенов нет вообще: цвет пишется по месту как литерал.
- `layouts/styles/*.yaml` — три файла (`button_layout`, `container_styles`, `page_styles`),
  **целиком закомментированы и ни на что не сослались**. Мёртвый задел под дизайн-систему.

### 1.7 Шрифты

| id | размер | glyphs | bitmap, байт | использований в YAML |
|---|---|---|---|---|
| `roboto_sm` | 16 | 116 | — | 31 |
| `roboto_md` | 20 | 116 | 6 596 | 14 (+ `default_font`) |
| `roboto_lg` | 24 | 116 | 9 353 | 7 |
| `roboto_xl` | 32 | 116 | 16 346 | 22 |
| `roboto_xxl` | 48 | 116 | **35 595** | **1** |
| `mdi_sm` | 20 | 74 | 8 251 | 2 |
| `mdi_md` | 26 | 74 | 14 046 | 19 |
| `mdi_lg` | 34 | 74 | 23 124 | 21 |
| `mdi_xl` | 42 | 74 | 35 631 | 17 |
| `mdi_xxl` | 50 | 74 | **49 996** | **1** |

- Все bpp = 4.
- Кириллица **не нужна**: все строки UI английские. Диапазон Roboto — дефолтный ASCII.
- Минимальный кегль — 16 px (`roboto_sm`), для 320×480 это на нижней границе, но приемлемо.

  и они компилируются во **все пять** размеров MDI.

### 1.8 Потоки
**Проблемы нет.** Ни `xTaskCreate`, ни FreeRTOS-задач в проекте нет. Все лямбды, скрипты и
колбэки сенсоров выполняются в главном цикле ESPHome, который же вызывает `lv_timer_handler()`.

### 1.9 Блокировки UI
- `vTaskDelay`, сетевых/NVS-операций внутри колбэков **нет**.
- `- delay:` встречается 3 раза (`sensors/settings.yaml:7,23`, `pages/energy.yaml:9`) — в ESPHome
  это **не блокирующий** delay, а планировщик. Отрисовку не морозит. Но это костыль-таймаут
  (см. P0-4), а не проблема блокировки.
- **Реальная проблема с CPU — другая**: `interval: 50ms` на каждую кнопку вентилятора
  (см. **P0-1**).

## 6. План работ

**Этап A (P0)** — 8 коммитов, каждый со сборкой:
1. Убрать 50 мс анимацию вентилятора (P0-1)
2. Починить сущность влажности гостиной (P0-2)
3. Единое безопасное форматирование чисел (P0-3)
4. Ширина + `long_mode` для значений датчиков (P0-4)
5. `lvgl.pause`/`resume` для сна экрана (P0-6)
6. Навигация `on_press` → `on_short_click` (P0-8)
7. Честный индикатор связи с HA (P0-7)
8. Токены цвета + исправление контраста (P0-5, зависит от **Q1**)

**Этап B (P1)** — дизайн-система и структура: токены → `stat_card` → шкала отступов →
дедупликация скриптов → нативный `bar` → чистка мёртвого кода и глифов → общая шапка панелей.

**Этап C (P2)** — состояния, анимации, полировка, deprecations.

## 7. Вопросы, требующие твоего решения

**Q1 — направление палитры (блокирует P0-5).** Контраст сейчас провален системно.
Три варианта:
- **(a) Затемнить поверхности** — рекомендую. Фон `0x1E2128`, карточка `0x2A2E38`
  (оба уже есть в проекте, панель климата так и выглядит). Приглушённый текст `0xB6BDC9`.
  Все семантические цвета берут 4.5 : 1. Минус: общий вид станет заметно темнее.
- **(b) Оставить фон, осветлить текст** до `0xDCE1E8`. Минимум визуальных изменений,
  но иерархия «основной / вторичный» почти исчезает.
- **(c) Оставить как есть**, зафиксировать в README как сознательный компромисс.

**Q2 — моношрифт для показаний (P2-7).** ТЗ требует. Цена — ещё один шрифт во flash
(~15–20 КБ, если ограничить глифы цифрами и `.-°%`). Варианты: (a) добавить Roboto Mono
только для цифр; (b) обойтись правым выравниванием в фиксированной колонке (0 КБ);
(c) не трогать.

**Q3 — секунды в часах (P2-4).** Убрать секунды (`%H:%M`) — перерисовка раз в минуту вместо
раза в секунду. Оставить — как сейчас. Что важнее?

**Q4 — сущность влажности гостиной (P0-2).** Сейчас стоит `sensor.bedroom_temp_humidity`.
Судя по соседней строке, температура берётся с `sensor.livingroom_temp_temperature` —
скорее всего верное имя `sensor.livingroom_temp_humidity`. Подтверди.

**Q5 — deprecations железа (P2-12, P2-13).** ТЗ запрещает мне трогать драйверы и тайминги
без согласования. Два кандидата: `qspi_dbi` → `mipi_spi` (смена драйвера дисплея, риск
подобрать не те параметры вслепую) и удаление игнорируемого блока `platformio_options`
(безопасно, сборка сама говорит, что он не действует). Трогать? Я бы **сейчас не трогал
драйвер**, а `platformio_options` удалил.

**Q6 — кадровый буфер.** Сейчас полный кадр 300 КБ **в PSRAM**, один буфер. Отрисовка в
PSRAM медленнее внутренней SRAM. Альтернатива — `buffer_size: 25%` (75 КБ, помещается во
внутреннюю RAM, запас там есть: занято 37.8 %). Это может заметно ускорить отрисовку, но
меняет тайминги вывода — трогаю только с твоего согласия и с проверкой на устройстве.
